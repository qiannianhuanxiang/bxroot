## 2. ⚠️ 两个与 INTEGRATION.md 不一致的地方（重要）

### 2.1 `__dso_handle` 未定义 → 链接失败（文档没提，实测必踩）

按 INTEGRATION.md §1.1 的命令（补上 `-I<proc>`）链接，会得到：

```
/usr/bin/ld: /usr/lib/aarch64-linux-gnu/libc_nonshared.a(pthread_atfork.oS):
              in function `__pthread_atfork': undefined reference to `__dso_handle'
/usr/bin/ld: hidden symbol `__dso_handle' isn't defined
/usr/bin/ld: final link failed: bad value
```

**根因**：`proc.c` 的 `px_runtime_init()` 调 `pthread_atfork`。glibc 把它放在
`libc_nonshared.a`，而那个归档需要 `__dso_handle` —— 正常提供者是 **crtbeginS.o**，
但本项目链接带 `-nostartfiles`，于是没人定义它。

这不是 proc.c 的 bug，是「`-nostartfiles` 的 .so 里用 `pthread_atfork`」的固有缺口。
INTEGRATION.md 的集成验证没暴露它，是因为那份验证的链接参数与生产不同。

**修法**（已在 `preload.c` 内实现，与 crtbegin 语义一致且保持 hidden）：

```c
void *__dso_handle __attribute__((visibility("hidden"))) = &__dso_handle;
```

已验证：`nm -D --defined-only` 里**看不到**它（hidden 生效，没污染命名空间）。

## 4. wait 家族：实现方式与 `WNOHANG` 处理

### 4.1 实现

新增 4 个钩子 + 3 个辅助（`preload.c`，`translate_path()` 之后）：

| 组件 | 职责 |
|---|---|
| `px_wait_delivered_exit(rc, status, options)` | **唯一判据**：这一次调用是否真的交付了一个「已终止」的子进程 |
| `px_note_reaped(pid)` | `px_ledger_reap(px_runtime_ledger(), pid)`，账本未初始化时静默跳过 |
| `px_waitid_delivered_exit(si, options)` | `waitid` 版本：看 `si_pid` 与 `si_code` |
| `waitpid` / `wait4` / `wait3` | `dlsym(RTLD_NEXT)` 懒加载 + 每次判空，转发后按判据记账 |
| `waitid` | 仅在 `idtype == P_PID / P_PIDFD` 时记账 |

### 4.2 「什么时候**不能**标 REAPED」

标错的代价比不做还大：`px_check_kill` 对 `PX_REAPED` 一律拒绝，所以把**活着的**
子进程标成 reaped = **从此杀不掉自己的孩子**。逐条：

| 情形 | 处理 | 理由 |
|---|---|---|
| **`WNOHANG` 返回 0** | ❌ 不标 | 子进程还没退出，全是 live（**题面特别点名的坑**） |
| `WNOHANG` 返回 -1（ECHILD/EINTR） | ❌ 不标 | 没有交付任何东西 |
| `status == NULL` | ❌ 不标（保守） | 无法区分「退出」与「停止」；代价只是退化成不回收 |
| `WIFSTOPPED` / `WIFCONTINUED`（`WUNTRACED`/`WCONTINUED`） | ❌ 不标 | 只是状态变化，进程还活着、还能被继续 wait |
| `waitid` 的 `si_pid == 0` | ❌ 不标 | `WNOHANG` 且无人可报（内核会清零 `siginfo`） |
| `waitid` 的 `si_code == CLD_STOPPED/CONTINUED` | ❌ 不标 | 同上 |
| `waitid` + `WNOWAIT` | ❌ 不标 | 僵尸被内核保留，还能再 wait |
| `waitid` 的 `P_ALL` / `P_PGID` | ❌ 不标 | `id` 不是 pid（`P_ALL` 时是 0/垃圾值），写进账本会污染 kill 判定 |
| `WIFEXITED` / `WIFSIGNALED` | ✅ 标 | 确实回收了 |

防止「`rc < 0` 判空写反」：判据用的是 **`rc > 0`** 与 **`si_pid > 0`**（不是 `< 0`）。
只要 `id_t` 比 `pid_t` 宽，`rc < 0` 就恒假，失败路径会被当成成功、把不存在的 pid
写进账本 —— 这类符号问题在跨 ABI 时才会暴露，所以按正数判定。

### 4.3 `WNOWAIT`：一个实测出来的内核差异（值得记进文档）

实测本容器内核（**6.1.145-android14**）：

```
waitid(P_PID, p, &si, WEXITED|WNOHANG|WNOWAIT) → 正常，僵尸被保留（si_pid=p）
wait4 (p, &st, WNOHANG|WNOWAIT, NULL)          → EINVAL(22)
```

即 **`WNOWAIT` 只对 `waitid` 生效**（Linux 从来不支持 `wait4` 的该位，glibc 也不拦）。
所以：

* `wait4`/`waitpid`/`wait3`：转发前**剥掉 `WNOWAIT`**（`PX_WAIT4_OPTIONS`），
  否则调用方会拿到一个它在本平台本来不会遇到的 `EINVAL`；
* 记账判据用**剥离后**的 options —— 既然我们让内核按普通 wait 回收了，就必须记账。
  （★ 这正是测试抓出来的一个真 bug：初版用原始 options 判定，于是「剥掉 WNOWAIT
  真的回收了」却永远不标 reaped —— 等于 WNOWAIT 路径上账本仍只增不减。已修。）
* `waitid`：原样转发，`WNOWAIT` 时**不标**（僵尸还在，标了就再也回收不了）。

### 4.4 专项测试（`test/RUN_WAIT_TESTS.sh`，14 用例 / 52 断言全过）

★ **必须如实说明这个测试的性质** ★ 它不是端到端 LD_PRELOAD 测试，而是
**同代码路径的插入等价测试**：

本容器有两条硬限制（都已实测）：

1. **`LD_PRELOAD` 完全不被采纳** —— 连一个只打印一行的玩具 preload 都收不到
   （外层 proot 的运行时会避开它）；
2. **`RTLD_NEXT` 到 libc 不可用** —— `dlopen` 之后 `dlsym(RTLD_NEXT, "getpid")`
   返回 NULL 并报 `undefined symbol: getpid`。

于是测试用 `test/waitstub.c` 构造等价场景：

```
① dlopen(产物, RTLD_GLOBAL)         ← 排在前面（= preload 的效果）
② dlopen(libwaitstub.so, RTLD_GLOBAL) ← 排在后面，充当「真实实现」
③ dlsym(产物句柄, "waitpid") 拿钩子本体直接调用
```

钩子内部的 `RTLD_NEXT` 会命中 stub → **与真实 preload 走完全相同的代码路径与分支**，
只差最底层是 `syscall()` 直调而非 glibc 包装。测试还逐条断言
「stub 确实被调用过」（否则说明钩子自己吞了调用没转发）。

覆盖：正常退出 / **WNOHANG=0 不误标** / wait4 / wait4+WNOHANG / wait3 /
waitid(P_PID) / waitid+WNOHANG 无子进程（不把 pid 0 写进账本）/ **WUNTRACED 停住不误标** /
WNOWAIT 兼容 / **waitid+WNOWAIT 保持 LIVE** / ECHILD 不污染账本 /
**30 轮 fork+waitpid 后账本无残留 LIVE（残留=1，仅自身）**。

最后一条直接钉住 REPORT §9 的退化风险：账本确实**会**随 wait 回收，
不再是「只增不减 → fork EAGAIN」。
