## 一、缺口（按优先级）

**⭐ #407 link2symlink 未拦 getdents64（open, 0评）** l2s 硬链接在 `find . -type l` 下现形。
- bxroot：全 src 无 getdents/getdents64 钩子（grep 证实），l2s 伪装只覆盖 stat/lstat/readlink/scandir → 同病。lstat 报普通文件而 getdents d_type 报 DT_LNK。
- 验证：`bxroot -l <rootfs> sh -c 'touch f; ln f h; find . -type l'`。钩子：getdents64(+getdents32)，在 preload.c scandir(5354) 同族加 d_type 改写。
- ★ **只有动手才会发现的约束**：glibc 的 `readdir` 用**本地 bl** 直调 `getdents64`（`objdump -d libc.so.6` → `bl bcb80 <getdents64@@GLIBC_2.30>`，不经 PLT）。所以**只 hook `getdents64` 符号抓不到 `readdir`** —— 必须同时 hook glibc 导出的 `readdir`/`readdir64`，并另在 `syscall_guard.c` 给裸 `syscall(61)` 加结果缓冲改写（node/libuv 走裸 svc）。漏任一条 = 「看起来修了、pnpm 依然失败」的假修复。

**⭐ #418 硬链接文件元数据自相矛盾：scandir 报 symlink、lstat 报 regular（open, 0评）** pnpm/Turbopack "Invalid symlink" 构建失败。
- 与 #407 同根：目录项流经 getdents，未经 l2s 伪装层，与 lstat(1631) 的 S_IFREG 伪装冲突。docs/l2s-stat伪装三缺陷分析.md 已记录 cp -a 同族矛盾，#418 是官方用户的真实生产损失 → 补 getdents 钩子一并解决。

**⭐ l2s 相对路径断链（docs/缺陷-l2s相对路径断链-git仓库损坏.md，git 仓库损坏）**
- 本地 430 条按 l2s/link2symlink×relative/cwd 组合检索，**无官方同类 issue**（#28/#95/#132 只谈清理与用法）→ 无上游解法可摘；修复按该文档"方案（推荐）"：l2s_rt_link 入口 getcwd+拼接绝对化，仅动 l2s-runtime.c 入口。
- 验证：文档内最小复现两形态对照 + RUN_L2S_ENTRYPOINTS.sh 回归。

**⭐ #8 unix socket 路径翻译残留：sendto/recvfrom（closed 但官方只做了 bind/connect）**
- bxroot 已覆盖 AF_UNIX bind/connect（preload.c:7194/7235，含抽象命名空间排除与 108 字节上限）；但 sendmsg/recvmsg **纯转发**（preload.c:7313/7322），`sendto`/`recvfrom` **根本没有钩子**（全树 grep = 0），`msg_name` 全树 0 命中 → sendto(AF_UNIX, SOCK_DGRAM) 的 sun_path 不翻译 → X11/XDG 类 DGRAM socket 缺口。
- 验证：`bxroot <rootfs> 探针 sendto 相对根 socket 路径`，strace 看落点是否进 rootfs。钩子：sendto/recvfrom 入参/出参 sockaddr_un。
- ★ **已有探针覆盖不到本缺口**：`test/probe_afunix.c` 存在但 (a) **没有任何 runner**（`RUN_ALL.sh` 里 0 命中），且 (b) 它的 T3 用 `SOCK_STREAM + send/recv` 回环 —— `send()`/`recv()` **不携带地址**，压根测不到 DGRAM。接线时必须补一条真正的 `SOCK_DGRAM + sendto` 用例。

**⭐ #64 -w 与 bind 目标一致时 cwd 未归一（closed, 官方 v4.0.1 改设 $PWD）**
- bxroot：launcher 只 setenv BXROOT_* 变量（launcher.c:982-1042），未见 setenv("PWD", workdir)；bash 的 pwd 内建在 "." 与 $PWD 同 inode 时原样回显 $PWD，可能漏宿主路径。
- 验证：`cd /tmp/a && bxroot -r <rootfs> -b /tmp/a:/test -w /test bash -c 'pwd'`。修法：launcher exec 前设 PWD=cfg.workdir。

- **#62 bind 覆盖 symlink 目标**：官方判定为默认语义（需 "!" 才穿透），bxroot 按路径前缀翻译行为一致，非缺陷。
- **#131/#28 l2s 中间文件清理/命名**：2026-09-26 在 bxroot-run 链路下 `BXROOT_LINK2SYMLINK=1` 实测（集中/散落两种布局，先以外层 readlink 指到 `.l2s.*` 证明 l2s 真生效），与官方 runtime 同 bridge/linker 换 `--preload` 对照：
  - 正确（钉住）：`ln a b; rm a` → b nlink=1 可读；`rm b` → 中间层/数据文件/.cnt 三件全部回收；`ln a b; rm b` → a nlink=1（a 仍是指向中间层的符号链接，计数正确）；`mv b c`（搬链接本身）计数不变、链完好；libc `unlinkat` 记账正确。
  - **缺陷 ①（已修）裸 `syscall(SYS_unlinkat)` 不记账**：只翻译路径然后让内核删符号链接，`.cnt` 不减 → 另一名字 nlink 停在 2 → 最后一次 unlink 只减到 1 → 三个中间文件永久残留（集中目录或客户目录）。官方 nlink 正确回到 1。修：`syscall_guard.c` 在 svc 前接 `l2s_rt_unlink`（与 libc 钩子同源，含懒启用、AT_REMOVEDIR 排除）。
  - **缺陷 ②（已修）rename 覆盖伪造链接不记账**（`mv c b`，b 是 l2s 链接）：libc rename/renameat/renameat2 与裸 38/276 都缺；内核用 c 顶掉符号链接 b，`.cnt` 仍 2 → a 报 nlink=2 → `rm a` 后残留。l2s-runtime.c 原注释称"参考实现同样存在、接受残留"—— 实测不成立（官方导出 `link2symlink_pre_rename_replace`，且 `rm a` 后无残留）。修：新增 `l2s_rt_rename_replace_prepare/commit`（svc 前判定、成功后递减/回收；old/new 是同一链两个名字时按 Linux 语义 no-op，RENAME_NOREPLACE/EXCHANGE 不记账）。
  - 命名/暴露：中间名固定前缀 `.l2s.<basename>NNNN[.NNNN[.cnt]]`，与用户文件冲突需用户主动起该名；散落布局 `ls -a` 可见 `.l2s.*`（已知非缺陷）；集中目录只在 `/` 出现，`/tmp` 与工作目录列举中不出现（测试断言）。
  - 官方本身偏离 Linux 语义之处（bxroot 不跟随）：覆盖后官方仍报 a nlink=2；同一链两名互 rename 官方把源名删掉（Linux 是 no-op）；三名链官方 lstat 报 4（stat 报 3）。
  - 回归：`test/RUN_L2S_CLEANUP.sh`（10 用例 × 2 布局，期望取 Linux 语义，官方输出作对照信息；撤修复后 nlink 漂移 + 集中目录残留 15 个 → 红）。
