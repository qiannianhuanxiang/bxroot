## 一、身份查询族：`getresuid` / `getresgid` / `getgroups`

### 无 runtime（纯 ldso 基线）

```
libc : getresuid rc=0 r=10655 e=10655 s=10655 errno=0
libc : getresgid rc=0 r=10655 e=10655 s=10655 errno=0
libc : getgroups(0,NULL)=6 errno=0
libc : getgroups(6,list)=6 [1077,3003,9997,20655,50655,99909997]
sym  : getresuid(148) rc=0 r=10655 e=10655 s=10655 errno=0 哨兵=完好
sym  : getresgid(150) rc=0 r=10655 e=10655 s=10655 errno=0 哨兵=完好
sym  : getgroups(158,0,NULL)=6 errno=0
sym  : getgroups(158,6,list)=6 [...] errno=0
sym  : getgroups(158,1,list) 在 n=6 时 =-1 errno=22     ← EINVAL：缓冲区太小
svc  : getresuid(148) rc=0 r=10655 e=10655 s=10655
svc  : getresgid(150) rc=0 r=10655 e=10655 s=10655
svc  : getgroups(158,0,NULL)=6
sym  : getresuid(148,NULL,NULL,NULL) rc=-1 errno=14     ← EFAULT：全 NULL 非法
sym  : getresuid(148,&r,NULL,NULL) rc=-1 r=10655 errno=14
```

**注意最后两行**：`getresuid(NULL,NULL,NULL)` 与 `getresuid(&r,NULL,NULL)`
在原生下都是 **EFAULT**。而 `getresuid` 的语义是"可以只取其中一部分" ——
所以这不是"NULL 非法"，而是**至少要有非 NULL 的**（内核要求至少一个有效指针）。
实现时必须**逐项判空**，不能因为一个 NULL 就整体失败。

### 官方（PROROOT_*）

```
libc : getresuid rc=0 r=0 e=0 s=0 errno=0
libc : getresgid rc=0 r=0 e=0 s=0 errno=0
libc : getgroups(0,NULL)=1 errno=0                      ← ★ 1 个组，不是 6
libc : getgroups(1,list)=1 [0]
sym  : getresuid(148) rc=0 r=0 e=0 s=0 errno=0 哨兵=完好
sym  : getresgid(150) rc=0 r=0 e=0 s=0 errno=0 哨兵=完好
sym  : getgroups(158,0,NULL)=1 errno=0
sym  : getgroups(158,1,list)=1 [0] errno=0
sym  : getgroups(158,1,list) 在 n=1 时 =1 errno=0
svc  : getresuid(148) rc=0 r=10655 e=10655 s=10655      ← ★ svc 层不伪造
svc  : getresgid(150) rc=0 r=10655 e=10655 s=10655
svc  : getgroups(158,0,NULL)=6
sym  : getresuid(148,NULL,NULL,NULL) rc=0 errno=0       ← ★ 官方不返回 EFAULT！
sym  : getresuid(148,&r,NULL,NULL) rc=0 r=0 errno=0
```

三点关键：
1. **`getgroups` 官方返回 1 个组 `[0]`**（root 主组），而原生是 6 个 —— 官方
   把补充组表**也伪造了**，与 `gid=0` 一致。
2. **`svc` 层官方不伪造**（148/150/158 都返回真值 10655/6）—— 与我在
   `docs/身份伪造只在符号层.md` 里更正过的结论一致：官方只覆盖
   `libc 符号 + syscall() 符号`。
3. **`getresuid(NULL,NULL,NULL)` 官方 rc=0** —— 与原生 EFAULT **不一致**。
   这可能是官方的实现缺陷，也可能是有意宽容。**跟进时需决定要不要照抄。**

### bxroot（BXROOT_*，fakeroot=1）

```
libc : getresuid rc=0 r=0 e=0 s=0 errno=0               ← libc 符号层已伪造
libc : getresgid rc=0 r=0 e=0 s=0 errno=0
libc : getgroups(0,NULL)=0 errno=0                      ← ★ 0 个组（与官方 1 不符）
sym  : getresuid(148) rc=0 r=10655 e=10655 s=10655      ← ★ syscall() 层未伪造
sym  : getresgid(150) rc=0 r=10655 e=10655 s=10655      ← ★ 同上
sym  : getgroups(158,0,NULL)=6 errno=0                  ← ★ 未伪造
sym  : getgroups(158,6,list)=6 [...]
sym  : getgroups(158,1,list) 在 n=6 时 =-1 errno=22
svc  : getresuid(148) rc=0 r=10655 e=10655 s=10655
sym  : getresuid(148,NULL,NULL,NULL) rc=-1 errno=14     ← EFAULT（与原生同，
                                                          与官方不同）
```

**缺口汇总（bxroot vs 官方）**：

| 项 | 官方 | bxroot | 缺口 |
|---|---|---|---|
| `syscall(148)` getresuid | 0/0/0 | 10655 | ★ B |
| `syscall(150)` getresgid | 0/0/0 | 10655 | ★ B |
| `syscall(158)` getgroups | 1 个 `[0]` | 6 个 | ★ B |
| `getgroups` 符号层 | 1 个 `[0]` | **0 个** | ★ 另一处不一致 |

> **额外发现**：bxroot 的 `getgroups` **符号层**返回 0 个组，而官方返回 1 个
> `[0]`。这**不在原任务的缺口 B 描述里**（B 只说了 syscall 层），
> 说明符号层与 syscall 层**各自都需要对齐**。

## 二、降权族：九个 setter

### 官方（PROROOT_*）

```
libc setreuid(-1,-1)     rc=0   errno=0
libc setregid(-1,-1)     rc=0   errno=0
libc setuid(999)         rc=0   errno=0
libc setgid(999)         rc=0   errno=0
libc setresuid(-1,-1,-1) rc=0   errno=0
libc setresgid(-1,-1,-1) rc=0   errno=0
libc setgroups(0,NULL)   rc=0   errno=0
libc setfsuid(999)       rc=999 errno=0     ← 返回旧值语义
libc setfsgid(999)       rc=999 errno=0
--- 裸 svc 层 ---
svc setreuid(143)     rc=0
svc setregid(145)     rc=0
svc setuid(146)       rc=0
svc setgid(144)       rc=0
svc setresuid(147)    rc=4294967295 (-1)    ← ★ 与 libc 不同
svc setresgid(149)    rc=0
svc setgroups(159)    rc=0
svc setfsuid(151)     rc=999
svc setfsgid(152)     rc=3342938152         ← 怪值（旧值语义）
--- 回读身份（libc）---
getuid=999 geteuid=999 getgid=999 getegid=999     ← ★★★
getresuid=999/999/999 getresgid=999/999/0 ngroups=0
```

### ★★★ 最重要的发现：官方**不是"假装成功"，而是"有状态的身份账本" ★★★

先前子代理的表述是「官方让这些调用返回 0，但**内核实际没有改变任何身份**，
程序会以为自己已降权」。**这句话只对了一半。**

实测**回读**证明：官方 setter 生效后，`getuid/geteuid/getgid/getegid`
**全部变成 999**。也就是说官方在**用户态维护了一份身份账本**：

- setter 写账本（并返回成功）
- getter 读账本

**我独立复现了这一点**（探针 `/root/vfy/ledger.c`，一次进程内先 set 再 get）：

```
########## 官方 libproroot-runtime.so ##########
BEFORE: getuid=0 getgid=0 ngroups=1
setgid(999) rc=0 errno=0
setuid(999) rc=0 errno=0
AFTER : getuid=999 getgid=999 ngroups=1      ← ★★★ 回读真的变了
AFTER groups n=1 first=0 errno=0

########## bxroot libbxroot-runtime.so ##########
BEFORE: getuid=0 getgid=0 ngroups=0          ← ★ 与官方差 1 个组
setgid(999) rc=-1 errno=38 (ENOSYS)
setuid(999) rc=-1 errno=38
AFTER : getuid=0 getgid=0 ngroups=0          ← setter 失败，账本也没动
AFTER groups n=0 first=-1 errno=0
```

这与"单纯返回 0"有本质区别：

| 实现方式 | setter 返回 | 回读 getter | 程序观察到的世界 |
|---|---|---|---|
| 单纯返回 0 | 成功 | **真实身份** | **自相矛盾**（说降了却没降）|
| 官方（实测） | 成功 | **999** | **自洽**（看起来真降了）|

**这改变了修法的性质**：不是"让几个号返回 0"，而是"实现一份用户态
身份账本，setter 与 getter 同源读写"。工作量与风险都显著高于原判断。

而且**这解释了为什么 `chage` 两侧不一致**：
- 官方：`getuid()` 返回 999（账本），`chage` 认为"我已降权" → 继续正常执行
- bxroot：`getuid()` 返回 0（fakeroot），但 `setgroups` 返回 ENOSYS →
  `chage` 报 `failed to drop privileges`

> 顺带注意：官方 `setgid(999)` 后 `getgid=999` 但 `getgroups` 首项仍是 `0`
> —— 补充组表**没有**跟着 gid 变。这是官方账本的一处**内部不一致**，
> 跟进时需有意决定要不要照抄（**不要盲目逐位复刻**）。
>
> 另注：`setfsuid`/`setfsgid` 的返回是**旧值**语义（官方 999），
> 而 `svc setfsgid(152)` 返回 `3342938152`（看起来是未初始化/怪异值）——
> 这一层需要单独核实，**不要照抄**。

## 三、对修法的含义（供后续任务参考）

1. **缺口 B（身份查询）相对独立、风险低**，可先做。但要注意：
   - 符号层与 syscall 层**都要对齐**（bxroot 的 `getgroups` 符号层返回 0 个组，
     官方是 1 个 `[0]`）
   - `getresuid/getresgid` 的**逐项判空**语义：原生对全 NULL 返回 EFAULT，
     但对"部分 NULL"是允许的（至少一个非 NULL）
   - `getgroups` 的双重返回语义（查询长度 vs 取列表）+ 缓冲区太小返回 EINVAL
   - **官方对 `getresuid(NULL,NULL,NULL)` 返回 0 而非 EFAULT** —— 这是一处
     官方与原生不一致，跟进时需有意决定

2. **缺口 C（降权族）比原判断复杂得多**：不是"让 143/145 返回 0"，
   而是要实现**用户态身份账本**（setter 写、getter 读、两者同源）。
   子代理先前发现的"只需 `{143,145}` 两个号就能让 `chage` 退出码变 0"
   仍然成立，但那只是**让 chage 不报错**的最低条件；
   要**真正与官方行为一致**（回读也一致），需要完整账本。

   > 这是一个重要的区分：**"让受害者命令通过" ≠ "行为与官方一致"**。
   > 前者是子代理实测的最小集，后者才是"兼容官方"的目标。

3. **`sigsys.c` 的 ENOSYS 契约不能被破坏**（libuv 回退 epoll 依赖它）；
   表外每个号必须逐字不变。
