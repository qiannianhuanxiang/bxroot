# 三后端对照基准（2026-10-13）

脚本：[`test/host/bench_backends.py`](../test/host/bench_backends.py)。本次是 **proot(ptrace) 对 bxroot 两方对比**，官方 proroot 后端被自检作废（见下）。

## 环境

| 项 | 值 |
|---|---|
| 设备 | Android，kernel 6.1.145，aarch64，原生 Termux（UID 10399，`TracerPid: 0`，非 PRoot） |
| rootfs | `~/dsharf`（Ubuntu glibc，约 308 MB；没有 node / git / grep） |
| proot | Termux 自带版本，版本号未记录；是否启用 seccomp 过滤加速未核实 |
| bxroot runtime | v0.2.4 默认 profile，SHA-256 `ee4e2276722809423ce2d7402766508f4f6ea5545a5178361e1a00e49ff0c96a` |
| 三后端共同条件 | 同一 rootfs；bind `/dev /proc /sys`；fakeroot；link2symlink |
| 方法 | 每项先预热并校验成功，再交替顺序跑 5 轮，取中位数；失败即作废该后端该项 |

自检：proot 的 guest `TracerPid=26725`（确在 ptrace）；bxroot `TracerPid=0`；两者 `find /usr` 均为 **8413** 项，遍历的是同一棵树。

## 结果

中位数（最小–最大），单位秒，n=5。

| 负载 | proot | bxroot | proot ÷ bxroot |
|---|---|---|---|
| `find /usr` | 2.822（1.948–4.604） | 0.163（0.158–0.192） | 17.3 |
| 外部 `stat` ×2000 | 41.07（29.26–75.23） | 12.23（11.81–13.74） | 3.36 |
| 小文件写后读回 ×300 | 6.398（4.100–8.824） | 1.964（1.684–2.965） | 3.26 |
| 硬链接 ×200 | 1.626（1.566–1.740） | 1.074（1.066–1.156） | 1.51 |
| fork+exec `/bin/true` ×300 | 1.704（1.635–1.886） | 1.391（1.348–1.416） | 1.23 |

五项里 proot 的最小值都大于 bxroot 的最大值，区间互不重叠。

## 这些数字能说明什么，不能说明什么

- 负载是 shell 循环。"外部 `stat` ×2000" 是启动 2000 次 `/usr/bin/stat` 进程，**不是** stat 系统调用的微基准。
- 外部 `stat` 每次约 20 ms（proot）对 6 ms（bxroot），而 fork+exec `/bin/true` 每次约 5.7 ms 对 4.6 ms。`stat` 进程启动时走的系统调用更多，proot 的差距在这里被放大，与 ptrace 开销随被跟踪调用数增长一致，但本次没有 strace 计数，未证实。
- 差距**不是常数**。同一台手机早一轮实测（`runtime-v3.so` 旧构建，bxroot 当时没开 link2symlink）里，`find /usr` 为 9.4 倍，`stat` 为 1.6 倍，fork+exec 是 proot 更快（2.75 s 对 3.60 s）。两轮构建和条件不同，无法拆开原因，所以不要把上表倍数当作固定值。
- 绝对耗时随手机状态波动，两轮之间 bxroot 的 `stat` 从 24.7 s 变成 12.2 s。只能比同一轮里的相对关系。
- 只有一台设备、一个 rootfs、一轮 5 次。proot 的区间很宽（`stat` 29–75 s），中位数本身不稳。
- **没有和官方 proroot 比。** 见下。

## 官方后端为什么作废

官方 runtime 读 launcher 写的配置块（`PROROOT_CFG_FD`），不读环境变量里的 bind。脚本按 `src/runtime/preload.c` 里的偏移自己拼了一块，官方 runtime 没接受：guest 里 `find /usr` 为 0 项，自检把整个后端剔除。要比官方，需要用真实 launcher 生成的配置块。

首轮实测还暴露过两个脚本问题，均已修：校验阈值过松（`find` 返回 0 也放行）、官方后端 `/tmp` 不可写。

## 复现

```sh
export TMPDIR=${TMPDIR:-$PREFIX/tmp}; mkdir -p "$TMPDIR"
python3 test/host/bench_backends.py 2>&1 | tee ~/bench.log
```

必须在原生 Termux 里跑；脚本会拒绝被 ptrace 的进程。`BENCH_ROUNDS`、`BENCH_ROOTFS`、`BENCH_BX_RUNTIME` 可用环境变量覆盖。
